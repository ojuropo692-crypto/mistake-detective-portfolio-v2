\# 错词辨析 · 诊断型词汇学习原型



> AI 产品助理实习作品集｜从竞品洞察到可点击原型的完整闭环



\## 30 秒看懂



小学英语背单词产品只告诉你"错了"，不告诉你"为什么错"。

我用 5 款竞品验证出三个行业留白，收敛成一份 PRD，

再用 Figma 设计、用 Cursor 落成可点击的三页原型。



主线是一条完整的产品链路：研究 → 定义 → 设计 → 落地 → 留痕，

不是三份孤立的作业。



\## 我看到的机会（研究）



竞品：洪恩英语、墨墨背单词、小小不背、百词斩、多邻国

方法：5×8 功能矩阵，AI 初判 + 逐格人工复核；

证据分四级（√有直接证据 / △部分覆盖 / ×明确不支持 / ?证据不足）。



关键发现：

\- 错因诊断：三款在本次路径内未见，两款有入口但后台机制未披露

\- 独立掌握验证：五款均为△——有作答信号，但没有"撤掉提示出新题"的延迟检验

\- 分级提示：两款有√，但仅作为按需入口，完整闭环未证实



三个差异点（本产品的设计主张）：

\- D1 错因决定练法：短追问确认卡点 → 不同卡点进不同补救任务，并记录判断依据

\- D2 答对也看稳定性：对部分答对的题追加无提示新题，

&#x20; 区分"独立通过 / 帮助后完成 / 待验证"

\- D3 提示逐级给出：最小线索 → 词义对比 → 示范，记录用量并在撤除后重测



\## 我如何定义它（PRD 三页）



1\. 问题与定位：小学五年级词义辨析；

&#x20;  成功指标 = 总用时（含诊断/提示/补救/验证）+ 次日与第 7 天独立表现

2\. 功能与流程：P0/P1 清单；

&#x20;  核心流程 = 答错 → 点选式卡点诊断 → 核对题 → 按因换练 → 撤提示新题 → 决定减练

3\. 异常与验收：识别失败/无效输入/证据不足时保留"待确认"；

&#x20;  行为信号（用时、改答）只触发复核，不直接判蒙对；AI 只给候选，不自动判错因



\## 我如何把它做出来（设计 + 落地）



Figma 三页设计稿（393×852）：练习页 / 错题本 / 诊断报告，含三条原型跳转。

Cursor 静态原型：本地 mock 词例 clever / polite / quiet，三页可点击跳转，

不接 API、不做状态管理。



点击体验原型：

\- \[练习页](practice.html) — 按因练习，减练条跳错题本

\- \[错题本](mistake-book.html) — 三态列表，clever 回练习页、quiet 进诊断报告

\- \[诊断报告](diagnosis-report.html) — 用时构成、提示级别、减题趋势、复核完成率

\## 边界与反思



这是静态原型，刻意不接 API、不做状态管理——目标是验证产品思路与视觉呈现，

不是可上线产品。已知技术债（CSS 颜色硬编码、容器固定高度、间距 AI 估算）

在"交付截图"场景下不返工；若改为交付代码库则会优先处理。

能讲出理由的偏差是决策，讲不出的才是缺陷。



\## 我能做什么



\- 竞品调研：把模糊感受拆成可核对的功能矩阵，并诚实标注证据边界

\- 需求定义：写清 P0/P1、核心流程、异常与验收口径

\- 原型落地：用 Figma 出可点击原型，再用 vibe coding 把设计落成可点界面

\- 迭代与留痕：版本归档、改动对比、Git 提交、缺陷自审

\- 工具协作：把 AI 当执行者、自己做审核者，每一步都能讲清判断依据
